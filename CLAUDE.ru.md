# CLAUDE.md — точка входа в репозиторий (русский перевод, сокращённый)

Файл содержит только специфичные для репозитория ограничения и таблицу маршрутов. Оригинал: CLAUDE.md.

## Жёсткие ограничения

### Протокол и совместимость

- Перед отправкой ответа сверяйте через `tools/proto.ps1` класс ответа, field op, класс элементов массива и args code. Не угадывайте тип по имени поля.
- Массивные поля всегда отправляйте как пустой массив, не null.
- У новой команды обязан быть handler; заглушки «чтобы запустилось» запрещены.
- Форма ответа обязана проходить проверку контракта; временно отключать её нельзя.
- Базовая версия клиента — 4.0.25034; изменения протокола требуют основания в виде реального пакета и регрессионного сценария.

### Время и состояние

- Мировые часы всегда равны реальному UTC; `2/2` (308.f7) и `1/2` должны совпадать.
- Шкалы состояния (f0–f6 в 308) присылает сервер; клиент лишь сглаживает их около 10 секунд.

### Данные и хранение

- Миграции повторяемы, откатываемы и покрывают обновление старой базы (`IF NOT EXISTS`).
- Пишите только в базу игроков; статическая конфигурационная база (`ATTACH`) только для чтения.
- Операции записи (награды, расчёт, покупка, списание) — в транзакции с идемпотентной квитанцией (хэш токена + main + sub + call_id). Повтор с тем же call_id вернёт старый ответ.

### Сборка снасти и согласованность рыбы

- Источник истины — экземпляр удилища `f5`; `rig_component` — односторонняя проекция. Вываживание, расчёт и садок указывают на одну и ту же рыбу.

### Дисциплина изменений

- Минимальный diff, только файлы задачи; без попутного рефакторинга.
- После изменений прогоните проверки и приложите вывод.
- Новое ограничение должно ответить: какой конкретный инцидент и почему существующий механизм его не остановил.

### Метаправила

- Изменение красных линий, проверок и процессов идёт по пути ограничений (spec) и требует ревью мейнтейнера.
- ИИ-агент только исполняет ограничения; при конфликте с кодом сообщает (issue/PR) и сам документы ограничений не правит.

## Критерии завершения

1. Прогнаны `make test` (или `go test ./...`), `go vet ./...`, `go build ./...`?
2. Не нарушены красные линии?
3. Где тест поведения и краснеет ли он после отката?
4. Нет ли в diff посторонних файлов?
5. Проверка на реальном клиенте/командами, а не «наверное, нормально»?
