# Изоляция статических данных

`rf4server` хранит записываемые данные игроков отдельно от статического игрового каталога, доступного только для чтения.

- Основная база данных: `sqlite.path`, обычно `data/rf4server.db`.
- Статический каталог: `sqlite.static_path`, обычно `server_data/static.sqlite3`.

## Модель во время работы

Каждое физическое соединение с базой данных подключает статический каталог как схему `static` в режиме SQLite только для чтения. Для каждой статической таблицы создаётся временное представление с тем же именем, которое читает данные из `static.<table>`.

Благодаря этому запросы без указания схемы, например `SELECT ... FROM item_def`, напрямую читают подключённый статический каталог, и не нужно писать имя схемы в каждом SQL-запросе. Временные представления также скрывают копию для совместимости, хранящуюся в основной базе данных.

Когда пул соединений создаёт новое физическое соединение, коннектор базы данных заново выполняет подключение и настройку представлений.

## Защита от записи

После завершения миграций SQLite authorizer отклоняет следующие изменения статического каталога:

- `INSERT`, `UPDATE` и `DELETE` для статических таблиц.
- DDL, который создаёт, удаляет, изменяет или перестраивает индексы статических объектов.
- Дополнительные операторы `ATTACH` или `DETACH` во время работы.
- Использование `PRAGMA writable_schema`.

Подключённая схема также открывается в режиме только для чтения. Поэтому защита от записи действует и через SQL-авторизацию, и через режим базовой базы данных.

## Инициализация

`seed` импортирует 21 статическую таблицу в основную базу данных, чтобы поддерживать миграции, проверки схемы и инструменты, которым нужна копия для совместимости. Миграции выполняются до включения runtime authorizer, поэтому контролируемый импорт завершается успешно.

Во время обычной работы сервера чтение статических таблиц без схемы разрешается во временные представления. Единственный список статических таблиц находится в `StaticTables` в `internal/store/repos_integrity.go`.

## Конфигурация

```yaml
sqlite:
  path: "data/rf4server.db"
  static_path: "server_data/static.sqlite3"
```

`RF4_SQLITE_STATIC_PATH` переопределяет `sqlite.static_path`. Команды `seed` и `launcher` также принимают `-static-db`.

Launcher передаёт дочерним процессам явный путь к статической базе данных через `RF4_SQLITE_STATIC_PATH`.

## Проверка

- `internal/store/staticdb_test.go` проверяет создание представлений, затенение, отклонение записи и повторное подключение после замены соединения.
- `internal/seed/static_runtime_test.go` проверяет, что после фактического выполнения seed и запуска во время работы запросы без схемы читают только статическую схему.

Запустите оба теста командой:

```bash
go test ./internal/store ./internal/seed
```
