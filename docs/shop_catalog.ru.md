# Каталог магазина

Полки магазина разбираются по `store_id` на основе встроенных определений магазинов и статического каталога `shop_item`. Встроенные определения хранятся в `internal/store/assets/shop_kind_defs.json` и охватывают 205 магазинов из семи типов.

## Порядок разбора

Для известного магазина базовая полка выбирается в таком порядке:

1. Строки `shop_item` для этого магазина. Необязательная полка `shelf` для конкретного магазина только добавляет недостающие товары, при совпадении ID приоритет у цены и остатка из реальных записей.
2. Если реальных записей по магазину нет, используется полка `shelf` для конкретного магазина из встроенного определения (если есть).
3. Строки других магазинов того же типа и бренда.
4. Общий шаблон этого типа магазина.
5. Если нет ни определения, ни строк, используется пустая полка.

Полка `shelf` для конкретного магазина заносит только недостающие товары с чёткими основаниями в статическом прайсе. Она не заменяет существующие реальные записи и не выставляет по оценке не внесённые в реестр специальные товары. `tungus_015` (кооператив «Тунгусская») регистрирует `tungus_bot` и `tungus_12pack`. Цены берутся из статического `item_price`: `gold=22` и `gold=129`, цен в серебре нет, базовый остаток у обоих 1. Цена и кошелёк используют одну и ту же внутреннюю целую единицу (сотые), а не целые монеты золота, которые видит интерфейс. Не внесённая в реестр старая водка и её подарочные наборы не выставляются по оценке.

`cafestore_18` (кафе «Опал» на Медном озере) тоже регистрирует полку `shelf` для конкретного магазина: `small_coffee`, `big_coffee`, `hd_box`. Цены берутся из статического `item_price` (`gold=4/6/1`, базовый остаток по 1). Информация о бренде линейки cafe_ukleyka находится в колонке `item_def.kind`, а не в колонке `brand`. Общее пополнение по бренду (оно сравнивает только `brand`) этих трёх товаров не находит. Без этой регистрации магазин откатился бы к шаблону еды kind 1: клиент всё ещё открывал бы кафе и позволял заказать кофе, но `22/3` не нашёл бы цену и в итоге показал бы «Произошла внутренняя ошибка».

Неизвестный `store_id` возвращает пустую полку. Известный магазин пополняется товарами по существующим категориям, магазин бренда дополнительно ограничивается тем же брендом. Детали сборки отдельно не выставляются. Для уже существующих цен сохраняется исходная валюта. Товары без цены оцениваются по наивысшей цене той же серии в источнике или по медиане цены того же класса и стабильно повышаются на 0–10% по номеру товара.

Администрации выставляют навыковые книги категории 80 по белому списку `books` в каталоге магазина. В статическом `item_def` у этих книг бренд пуст, а категория отличается от категории карты в магазине, поэтому общее правило пополнения их не находит, а при отсутствии цены они не оцениваются. Белый список заведён по регионам: у `admin_012` (Норвежское море) только `seafish_book`, у `admin_18` (Медное озеро) только `feeder_book`, у `admin_01` (озеро Кмаролиноеzero) и `admin_19` (озеро Элк) по `float_fishing_book` и `spinning_book`. Все 4 навыковые книги единообразно получают эффективную цену в серебре 998500 и эффективную цену в золоте 500 (в статическом `item_price` и при пополнении полки значения берутся именно такие). Расчёт возможен и в серебре через `22/2`, и в золоте через `22/3`. Цену по-прежнему можно изменить отдельно через `shop_item_override` в админке.

После пополнения базовой полки по `(store_id, item_id)` применяется `shop_item_override`. Эта конфигурация может отдельно переопределять цену в серебре, цену в золоте и остаток. Переопределение действует только на соответствующий магазин. Товары за серебро и золото поставляются постоянно: если эффективный остаток равен 0, он автоматически пополняется до 1000. Обновление и перезапуск не меняют цены, баланс и рюкзак.

Просмотр магазина, расчёт покупки и API админки используют один и тот же путь разбора, поэтому показанная цена совпадает с расчётной.

## Объём охвата

Встроенные определения дают общие шаблоны полок для семи типов магазинов. У типа 2 (мастерские, 18 магазинов) и типа 8 (экскурсии и аренда, 3 магазина) базового шаблона нет. Пока не добавлены строки `shop_item` для конкретного магазина, полки этих магазинов остаются пустыми.

Чтобы изменить базовую полку, обновите статический каталог в `server_data/static.sqlite3` и заново запустите `seed`. Слой хранения отклоняет запись в статические таблицы во время работы.

Встроенные дополнения для конкретных магазинов ведутся в соответствующих записях `stores` в `internal/store/assets/shop_kind_defs.json`, сейчас они используются для двух особых товаров «Тунгусской» и трёх товаров кафе на Медном озере. При изменении нужно сверять статический прайс и синхронно обновлять тест проверки каталога (хэш каталога в `TestEmbeddedShopCatalogMatchesEvidenceAndCoversAllStores` изменится вместе с ним). Это не произвольный вход для выставления товаров. Не меняйте полку отдельного брендового магазина через изменение общего шаблона `kind`.

## Функции управления

Консоль может переопределять цену и остаток предметов, уже находящихся на полке. Удаление переопределения возвращает базовые значения. Для добавленных товаров переопределение тоже можно задать или удалить. Предметы, не относящиеся к категории или бренду магазина, по-прежнему нельзя принудительно выставить через переопределение.
