# Транзакция расчёта улова

Для каждой рыбы квитанция расчёта сохраняется по GUID рыбы. При первом успешном получении рыбы опыт и уровень, мастерство по способу ловли, износ снаряжения, запись о повреждениях и квитанция фиксируются в одной транзакции. Если любой шаг не удался, всё откатывается, а исходная рыба остаётся для повторной попытки.

При повторном запросе и после перезапуска процесса читается та же квитанция, опыт, мастерство и износ повторно не начисляются. Уведомления об уровне и улове отправляются только после первого успешного коммита. Разложение бонусов и приращение навыков, сохранённые в старых квитанциях, остаются читаемыми. У старых квитанций без поля приращения навыков остаётся прежнее значение для совместимости.

Помещение в садок, отпускание и инвентарь садка по-прежнему обрабатываются своими бизнес-входами. Эта транзакция не объединяет их в один коммит.

Целевой протокол — клиент 4.0.25034. Серверные тесты строят запросы по существующим структурам 14/4 и объектов расчёта. Переподключение реального клиента, повторные запросы, заполненный садок, продажа рыбы и отпускание всё равно требуют ручной приёмки, серверные тесты их не заменяют.
