# LEVEL_UP_GIFT_CARDS — механика карточек подарков за уровень (полное восстановление)

> Дата анализа: 2026-11-08 · базовая версия клиента **4.0.25034** (IL2CPP)
> Источники доказательств: декомпиляция GameAssembly в IDA + декомпилированный исходник IL2CPP (il2csharp_full) + библиотека документов перехвата monitor.
> Ссылки в тексте даны как относительные имена материалов, символов и адреса VA для сверки, локальных путей нет.

---

## 1. Вывод в одной фразе

**Подарок за уровень — не отдельная система, а «элемент стопки подарков» во всплывающем окне расчёта улова (GameResult)**:
сервер в ответе на расчёт отпускания (14/6→807) или получения рыбы (14/4→801) вкладывает в **массив 811** запись
с `видом=1 (новый уровень)` и прикладывает к ней массив предметов. Клиент, увидев `310.f1 = число повышений уровня за этот раз > 0`, отрисовывает предметы этой записи
в виде сетки карточек, заголовок — локализованный текст, отформатированный «текущим уровнем».

### 3.4 Получение уровня

«Текущий уровень» в заголовке и «старый уровень» при фильтрации конфигурации читаются из глобального синглтона игрового состояния (`nnfmkefpbdi` → объект +0x178 → +0xb0 int = уровень игрока). `старый уровень = текущий уровень − 310.число повышений`.

## 4. Путь через конфигурацию (локально на клиенте, конфигурационный blob 1/4)

`ljmgdbbnjke()` (вызывается в конце всех ctor, blehdkolhfl.cs:1155):

```
if (310.число повышений >= 1) {
    levelFrom = уровень игрока - 310.число повышений;  levelTo = уровень игрока;   // замыкание pofadojnfng

        .Where(hbdjhamgmnc: проверка поля платформы && проверка временного окна)
        .OrderBy(уровень)
        .Select(JsonValue → cgfegllkfea)
        .ToArray();
    this.ieihhhbliod = entries;
}
```

- `cgfegllkfea` (конфигурационный подарочный набор, dump.cs:37834): `fkjpeoodkfh`=lkbioeollij(11100) причина подарка, `jbandpaaagm`=mmphincpfjn[] (args 15000: {определения предметов[], причина}), 5×u64 окно временных меток, `dlmaaeecbci` (**уровень int** @0xA0), `nhjofmmmngl` (метка платформы string @0x98), `obifdihmcfn` (int[]).
- Прямое объяснение «карточки есть только на уровнях 1–10»: **таблица уровней подарков в серверной конфигурации заведена только для низких уровней**, а клиент дополнительно фильтрует по интервалу `(старый, новый]`.
- Обратите внимание: у `ieihhhbliod` на современном пути сборки окна потребителей не найдено (у getter нет внешних вызывающих), **основная цепочка — 811 с сервера**. Этот разбор конфигурации, по-видимому, резервный/старый путь, но служит косвенным подтверждением существования таблицы уровней.
- **Другой интерфейс подарков**: словарь 13020 `edihjhnglec` (blob 1/4, f0=systemID, f1/f2=временные метки, f3={systemID, количество, bool}[]) → запрос 3/28 → 13022 → `RUIGiftsExplorerPanel` (панель подарков / список для получения, player_p2.md §11). С окном повышения уровня он никак не связан.

## 7. Уровни доказательств и открытые вопросы

**[Подтверждено кодом]** (IDA + декомпилированный исходник, достоверно):
вся клиентская логика §3, разбор конфигурации §4, ключи локализации §5, структура 811, таблица полей 807.

**[Подтверждено перехватом]** (перехват официального сервера):
`310.f1 = число повышений` (девять образцов). У официального 807 на обычном отпускании 6 полей все null (повышения не было). Окно «новый уровень / подарок / +N очков навыков» управляется двумя полями 310.

**[Открытые вопросы]**
1. **Нет непустых образцов 811 в 807/801 официального сервера в момент повышения уровня**: все 4 образца 807 в monitor относятся к отпусканию без повышения. Перед воспроизведением нужно перехватить повышение уровня на низкоуровневом аккаунте, сверить реальное заполнение f0/f1/f2 записи f1 и то, несёт ли f3 (базовый массив предметов) параллельно сами подарки.
2. Смысл двух групп предметов 811.f2 и f3 не определён (обычные/премиум? обычные/редкие?). Нет образцов официального сервера, где в одной записи присутствуют обе группы.
3. Реальный потребитель `ieihhhbliod` (результат разбора конфигурации) не найден. Это не влияет на основную цепочку, но определяет, возможен ли режим «чисто через конфигурацию» (если официальный сервер при повышении не присылает 811, карточки могут отрисовываться по таблице конфигурации).
