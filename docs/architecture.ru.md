# Обзор архитектуры и реализации

## Связи компонентов

Стандартный релизный пакет для Windows управляет двумя серверными процессами, gateway и gameserver, через launcher. Админка встроена во входную точку launcher. Данные игроков хранятся в локальной SQLite, отдельная база данных или брокер сообщений не нужны.

```text
Игровой клиент
   │ HTTPS :443 вход              TCP :9341 realtime-соединение
   ▼                              ▼
┌──────────────── gateway ────────────────┐
│ Вход и token / приём TCP и рукопожатие   │
│ Кодирование кадров / RC4 / ACK /         │
│ keepalive / перехват переподключения     │
└───────────────────┬─────────────────────┘
                    │ внутренний туннель PSK :9401
                    ▼
┌────────────── gameserver ────────────────┐
│ Диспетчер команд / страж пушей /         │
│ геймплей и расчёты                       │
│ Рыбалка / предметы / магазин / почта /   │
│ навыки и задания                         │
└───────────────────┬─────────────────────┘
                    ▼
        data/rf4server.db (данные игроков, WAL)
          + server_data/static.sqlite3
                 (только для чтения во время работы)
                    ▲
┌────────────── launcher :9500 ────────────┐
│ Надзор за процессами / управление        │
│ запуском / логи / встроенная админка     │
└───────────���─────────────────────────────┘
```

- **gateway** — вход для клиента. Он поддерживает шифрование сессии и порядок передачи, после ACK пересылает запросы в gameserver, а также отвечает за keepalive и перехват переподключения.
- **gameserver** выполняет игровую логику, экономические транзакции, сохранение состояния и проверку контракта ответа. Административные команды обрабатываются через очередь команд в общей SQLite.
- **launcher / admin** даёт локальный центр управления и админку Control Deck. Админка использует JWT и встроенное SPA. При стандартном запуске отдельный порт 8080 не занимается. В контейнерных вариантах используется отдельный административный процесс, его вход описан в [руководстве по Docker Compose](../docker/README.ru.md) и [руководстве по одному контейнеру Docker](../DOCKER.ru.md).

Конфигурация, порты по умолчанию и команды ручного запуска описаны в [руководстве по развёртыванию](deploy.ru.md). Изоляция статического каталога и данных игроков описана в разделе [Изоляция статических данных](static_runtime_isolation.ru.md).

## Обзор текущей реализации

Ниже перечислены **главные цепочки и базовые механизмы**, которые в коде уже работают. Это не полный список функций:

- **Подключение и протокол**: HTTPS-вход и выдача token, рукопожатие realtime TCP, кодирование кадров, непрерывный шифропоток RC4, ACK, keepalive транспорта, переподключение после обрыва и перехват состояния RC4. Есть также проверка контракта ответа, страж пушей и протокольная заглушка, чтобы неизвестная команда не приводила клиент к немедленному краху.
- **Сессии и данные игрока**: управление несколькими сессиями, перехват при повторном подключении с тем же token, профиль игрока, уровень и опыт, серебро/золото/банк, карты и точки появления, путешествия, мировые часы, дерево навыков, достижения и записи об уловах.
- **Главная цепочка рыбалки**: заброс, попадание в воду, поклёвка, подсечка, вываживание, подмотка, расчёт, помещение в садок и отпускание. Поддерживаются типы удилищ, наживка, приманки, глубина ловли, клёв по водоёмам, короткое окно ритма для спиннинга, а также сохранение состояния рыбалки и восстановление при переподключении.
- **Предметы и снасти**: рюкзак и садок, экземпляры предметов и их свойства, сборка и разборка снасти, материализация подкомпонентов, прочность и износ, ремонт в мастерской, привязка к панели быстрого доступа.
- **Экономика и контент**: каталог магазина, серверное ценообразование, переопределение остатков, транзакции покупки и возврата, торговля на рыбном рынке, почта и вложения, крафт, соревнования, базовые социальные профили и записи.
- **Управление и эксплуатация**: админка Control Deck (JWT + встроенное SPA), управление игроками, инвентарём, навыками, магазином, клёвом и почтой, кик и бан, аудит операций. Launcher отвечает за надзор за процессами, проверки работоспособности и панель логов.
- **Хранение и надёжность**: SQLite WAL, миграции базы данных, подключение статической конфигурационной базы только для чтения через ATTACH, квитанции запросов и контроль идемпотентности, транзакционные экономические операции, уникальные ограничения и проверки целостности данных.
- **Приватность и обезличивание**: репозиторий не содержит ответов воспроизведения, GUID экземпляров, token и данных аккаунтов, которые можно связать с игроками. Протокольная заглушка использует только список структур, стартовые предметы создаются во время работы по статическим определениям.
- **Тесты и регрессия**: модульные и интеграционные тесты, тест кольца протокольного корпуса, а также специальные регрессии по ключевым цепочкам: рыбалка, экономика, сборка, переподключение.

Отдельное описание механик рыбалки см. в разделе [Механики рыбалки](gameplay.md).

## Краткий обзор каталогов

```text
cmd/launcher                        графический постоянный супервайзор (трей + панель)
cmd/gateway|gameserver|seed        процессы и инструмент инициализации официальной сборки
cmd/admin                           отдельная точка входа для отладки (стандартный launcher её не запускает)
internal/proto                      байтовый уровень протокола (кадры/RC4/метки значений/конверт)
internal/wiregen                    сгенерированная таблица типов (364 класса) + ворота кольца корпуса
internal/tunnel                     внутренний туннель шлюз ↔ основной сервер
internal/gateway                    HTTPS-вход / realtime TCP / сессии
internal/gameserver                 ядро сессии / обработчики / рыбалка / предметы / магазин
internal/store                      слой хранения SQLite + миграции
internal/admin                      API админки + встроенное SPA
docs/                               материалы по развёртыванию, реализации, геймплею и разработке
```
