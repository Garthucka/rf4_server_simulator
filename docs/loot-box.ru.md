# Подарочный набор за улов (случайное открытие)

После того как рыба поймана и успешно помещена в садок, с определённой вероятностью на месте открывается подарочный набор. Награда сразу попадает в рюкзак и объявляется в чате. Не нужно открывать рюкзак и не требуется поддержка нового протокола клиентом.

## Результат

Поймали рыбу → **успешное помещение в садок** (14/5) → с вероятностью срабатывает набор → сервер на месте бросает кубик → награда сразу в рюкзаке → объявление в чате: «Поймали праздничный набор, выпало: XXX ×N».

При поимке трофейной (3) или «синекоронной» (4) рыбы по умолчанию обязательно выпадает один набор как гарантия.

## Конфигурация

Задаётся в `kv.loot_box_defs` (JSON). После изменения вступает в силу в течение 30 секунд без перезапуска:

```json
[
  {
    "id": "event_box",
    "name": "Праздничный набор",
    "chance": 0.05,
    "rewards": [
      {"item_id": "worm_01", "qty": 2, "weight": 40},
      {"item_id": "bait_dreissena", "qty": 1, "weight": 30}
    ]
  }
]
```

| Поле | Описание |
|---|---|
| `chance` | Вероятность срабатывания при каждом улове (0~1) |
| `rewards` | Пул наград. **Если пусто, случайно выбирается один товар с остатком на полке магазина** |
| `rewards[].weight` | Относительный вес (не проценты) |
| `rewards[].qty` | Количество. Для штучных предметов (удилище/катушка) каждый экземпляр отдельный, количество всегда 1 |
| `carrier_item` / `carrier_qty` | Необязательно: «видимый мешок», который дополнительно выдаётся при открытии |

Способ записи (основная база):

```sql
INSERT INTO kv(k,v) VALUES('loot_box_defs','[...]')
  ON CONFLICT(k) DO UPDATE SET v=excluded.v;
```

## Переключатели

**По умолчанию выключено**: чтобы набор срабатывал, нужно установить общий переключатель в 1 в разделе «Параметры игры → Подарочный набор за улов».

| Параметр | По умолчанию | Описание |
|---|---|---|
| `loot_box_enabled` | 0 | Общий переключатель. 1 включает (бросок и выдача), 0 полностью отключает |
| `loot_box_chance` | пусто | Переопределяет `chance` из конфигурации. Пусто означает «по конфигурации» |
| `loot_box_trophy_guarantee` | 1 | При включении поимка трофейной или «синекоронной» рыбы всегда открывает один набор |

## Основные моменты реализации

- Вход: после успешного `fishingKeep` (помещение в садок 14/5) вызывается асинхронно, ответ не блокируется.
- Розыгрыш: если настроены `rewards`, выбор по весам. Иначе случайный товар из `shop_item` с `stock>0`.
- Проверка допустимости: случайная награда и `rewards` исключают категории 55 (наборы-коробки) и 73 (подарочные мешки) и требуют, чтобы у категории было авторитетное отображение `categoryWireClass`. `carrier_item` тоже должен корректно материализоваться. Элементы конфигурации, которые нельзя выдать, пропускаются.
- Выдача: `AddToStack` → `pushItemUpdate` (4/22) → объявление в чате.
- Идемпотентность: повторный 14/5 для той же рыбы вызывает набор только один раз.
- Отказоустойчивость: при ошибке записи в базу пишется только Warn, на результат помещения в садок это не влияет. У горутины есть recover.

## Почему не используется всплывающее окно открытия на клиенте

У клиентского `10304 Пакет награды` поля заведены в таблице wiregen, но на сервере реализации нет, и нет реальной формы пакета, на которую можно опереться. Неверная форма приведёт к ошибке разбора на клиенте. Сейчас используется уже проверенный канал `4/22 обновление предмета + объявление в чате`.
