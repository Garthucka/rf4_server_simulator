# Развёртывание

Это руководство описывает локальное развёртывание `rf4server`. Формат протокола рассчитан на клиент RF4 **4.0.25034**.

## Использование релизного пакета для Windows

Если нужна только локальная игра, Go устанавливать и собирать ничего не нужно:

1. Скачайте Windows x64 ZIP из [стабильного релиза](https://github.com/OpenFisherCommunity/rf4_server_simulator/releases/latest) и распакуйте целиком, не выбирайте `Source code`. Чтобы попробовать недавно добавленные функции, выберите Preview в [списке всех релизов](https://github.com/OpenFisherCommunity/rf4_server_simulator/releases). Возможности и риски превью описаны в его release notes.
2. Прочитайте `快速开始.txt` («Быстрый старт.txt») внутри пакета. Релизный пакет содержит локальный сертификат для разработки `certs/server.crt`. Установите этот публичный сертификат в «Доверенные корневые центры сертификации» на этой машине. Он предназначен только для локального тестирования, не передавайте закрытый ключ.
3. С правами администратора отредактируйте файл hosts Windows `%SystemRoot%\System32\drivers\etc\hosts` и направьте `api.rf4game.ru` и `api.rf4game.com` на `127.0.0.1`. Переключить hosts можно и в центре управления launcher, запись тоже требует прав администратора. Если клиент запущен на другом компьютере, укажите доверенный адрес шлюза в локальной сети, подробнее см. [Подключение клиента](#подключение-клиента).
4. Дважды щёлкните `启动服务器.cmd` («Запуск сервера.cmd») или запустите `bin\launcher.exe` и дождитесь автоматической инициализации и проверок работоспособности. Откройте `http://127.0.0.1:9500/`, в разделе «Управление запуском» сохраните абсолютный путь к `rf4_x64.exe` и нажмите «Запустить игру».
5. В том же центре управления перейдите в админку. Администратор по умолчанию в релизном пакете для Windows: `admin` / `admin123`. Его нужно сменить в конфигурации. При самостоятельном развёртывании из шаблона действуют `admin.username` и `admin.password`.

Когда вы закончили локальную игру и хотите вернуться на официальные серверы, восстановите прежнее разрешение этих доменов в hosts. Панель launcher умеет переключать обратно на официальный адрес. Чтобы использовать автопереключение, задайте `launcher.hosts_switch: true` и запускайте с правами администратора. При выходе launcher восстановит записи hosts, которыми он управлял. Добавленные вручную записи нужно восстанавливать вручную, не удаляйте записи, которые ведут другие программы.

Значок launcher в трее показывает зелёным, жёлтым и красным соответственно «всё работает», «частично работает» и «всё остановлено». Из него можно открыть центр управления, перейти в админку, запускать и останавливать сервисы или выйти. Центр управления также умеет запускать, останавливать и перезапускать отдельные процессы, показывает логи в реальном времени и информацию о версии сборки. После сбоя сервиса перезапуск выполняется автоматически с экспоненциальной задержкой.

## Развёртывание в контейнерах

На Windows, macOS и Linux можно использовать многосервисный вариант [Docker Compose](../docker/README.ru.md) или [один контейнер Docker](../DOCKER.ru.md) на основе Dockerfile в корне. Выберите один из двух вариантов и не занимайте одни и те же порты хоста одновременно.

## Компоненты и порты

| Процесс | Порт по умолчанию | Назначение |
| --- | ---: | --- |
| `gateway` | 443/TCP | Точка HTTPS-входа. |
| `gateway` | 9341/TCP | Realtime-соединение игрового клиента. |
| `gameserver` | 9401/TCP | Внутренний туннель от шлюза к игровому серверу. Привязывайте только к доверенному сетевому интерфейсу. |
| `launcher` | 9500/TCP | Локальный центр управления, также отдаёт встроенную админку `/admin/`. |
| `gateway` | 9501/TCP | Проверки работоспособности и готовности, метрики и профилирование. |
| `gameserver` | 9502/TCP | Проверки работоспособности и готовности, метрики и профилирование. |

Точки наблюдения: `/healthz`, `/readyz`, `/metrics` и `/debug/pprof`.

## Предварительные условия

- Для сборки из исходников нужен Go 1.27.3 или новее.
- `launcher` требует Windows. Остальные серверные команды можно собирать на других платформах, которые поддерживает Go.
- Права на привязку к порту 443.
- Настроенные порты не заняты другими процессами.

## Сборка и настройка

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
Copy-Item config.example.yaml config.yaml
```

Можно также использовать `make build`, артефакты по умолчанию попадают в `bin/`. Зависимости реализованы на чистом Go, драйвер SQLite — `modernc.org/sqlite`, CGO не нужен. Команды проверки при разработке см. в [руководстве для контрибьюторов](../CONTRIBUTING.ru.md). Для проверки цикла протокольного корпуса запустите `make corpus`. Если локальных файлов корпуса нет, этот шаг автоматически пропускается.

Перед запуском отредактируйте `config.yaml`:

- Установите `gateway.advertise_host` равным адресу, по которому клиент может подключиться в реальном времени.
- Установите `gateway.login_domain` равным основному имени хоста входа. Сгенерированный сертификат покрывает это имя, `localhost` и `127.0.0.1`.
- Задайте одинаковые непустые значения для `gateway.tunnel.psk` и `game.tunnel.psk`.
- Перед открытием сервиса в любую сеть замените `admin.jwt_secret`, `admin.password` и PSK туннеля.
- Оставьте `sqlite.static_path` указывающим на поставляемый `server_data/static.sqlite3`.

`config.yaml` исключён через `.gitignore`. Загрузчик конфигурации поддерживает переопределения `RF4_*`, описанные в `config.example.yaml`.

Основные точки конфигурации:

- `config.example.yaml` — шаблон, хранящийся в репозитории. Фактически используется `config.yaml`, рабочую конфигурацию коммитить нельзя.
- `sqlite.path` указывает на базу игроков, `sqlite.static_path` — на статический каталог, доступный только для чтения во время работы.
- `launcher.game_path` хранит путь к клиенту, `launcher.game_region` по умолчанию `CN`.
- Переменные окружения, например `RF4_SQLITE_PATH`, `RF4_SQLITE_STATIC_PATH`, `RF4_LOG_LEVEL`, `RF4_GAME_CLIENT_PATH`, переопределяют соответствующие настройки. Полный список см. в [шаблоне конфигурации](../config.example.yaml).

Имя пользователя и пароль администратора из YAML применяются при запуске. Если учётной записи нет, она создаётся. Если у существующей записи пароль отличается, он сбрасывается на пароль из конфигурации.

## Инициализация данных

Перед запуском серверных процессов один раз запустите `seed`. Повторный запуск безопасен.

```powershell
bin\seed.exe -config config.yaml
```

Инициализация выполняет миграции базы данных, импортирует статический каталог, создаёт настроенный профиль игрока по умолчанию и создаёт или приводит в соответствие учётную запись администратора. Повторный запуск не удаляет данные игроков.

## Запуск

### Launcher

```text
bin\launcher.exe
```

При первом использовании launcher инициализирует базу данных, запускает `gameserver` и `gateway`, выполняет проверки работоспособности и перезапускает вышедшие процессы. Обработчик админки встроен прямо в launcher, единая точка входа — `http://127.0.0.1:9500`. Отдельный порт управления 8080 больше не слушается.

### Запуск игры из центра управления

На странице «Управление запуском» единого центра управления введите абсолютный путь к `rf4_x64.exe` и сохраните. Путь записывается в текущий `config.yaml`:

```yaml
launcher:
  game_path: 'D:\Games\RF4EN\Game\rf4_x64.exe'
  game_region: "CN"
```

После нажатия «Запустить игру» launcher напрямую выполняет:

```text
D:\Games\RF4EN\Game\rf4_x64.exe -region CN
```

Принимаются только вызовы со страницы того же источника на этой машине. Путь должен быть существующим абсолютным, а имя файла — `rf4_x64.exe`.

### Ручной запуск

Запустите следующие команды в отдельных терминалах:

```powershell
bin\gameserver.exe -config config.yaml
bin\gateway.exe -config config.yaml
```

Ручной запуск этих двух процессов не запускает консоль управления. Консоль управления предоставляется единой точкой входа `launcher` на порту 9500.

Учётные данные для локальной разработки в релизном пакете Windows по умолчанию — `admin` / `admin123`. При развёртывании из исходников используются учётные данные администратора из конфигурации. Для любой среды, не изолированной от локального компьютера, замените учётные данные и ключи в `config.yaml`.

## Самопроверка версии после развёртывания

Исполняемые файлы в `bin/` перезаписываются при любом запуске `build.ps1` / `tools/build.ps1` / `make build`, а все эти скрипты собирают из **каталога, в котором выполняются**. В репозитории часто одновременно существует несколько worktree. После перезаписи процесс продолжает работать на старом коде, и это не видно ни по `/healthz`, ни по трею, ни по логу запуска. Отсюда ситуация «развернул, а не подействовало».

После развёртывания нужно сверять **работающий процесс**, а не файл на диске:

```powershell
# Спросить сам процесс: какая это сборка и из какого каталога собрана
curl.exe -s http://127.0.0.1:9502/metrics | Select-String rf4_build_info

# Через launcher: running_build сообщает сам дочерний процесс, exe_changed означает, что файл на диске заменён
curl.exe -s http://127.0.0.1:9500/api/status
```

Нормальный вывод выглядит так:

```text
rf4_build_info{process="gameserver",version="20260101090000",buildts="20260101010000",commit="abc1234",source="<каталог checkout>"} 1
```

Основное:

- `source` — это **каталог checkout** на момент сборки (с прямыми слэшами), `commit` — короткий SHA соответствующего коммита, `buildts` — время сборки в UTC. У `bin/gameserver.exe` значение `source` должно быть именно тем worktree, который вы ожидаете. Несоответствие означает, что файл перезаписан другим checkout. Все пять точек сборки (`build.ps1` / `tools/build.ps1` / `make build` / `.github/scripts/build-preview.sh` / `build-release.sh`) автоматически подставляют эти четыре метки, вручную заполнять не нужно. У артефактов CI `commit` берётся из короткого `$GITHUB_SHA` запустившей сборку.
- Если `procs[].running_build` отсутствует или панель показывает «неизвестно», то порт наблюдения недоступен либо работает старая сборка без этих меток. Это нельзя считать «версия в порядке».
- Если `procs[].exe_changed` истинно, то exe на диске заменён, но процесс не перезапущен (панель одновременно показывает предупреждение, а в логе launcher появляется `WARN ... заменён`). В этом случае новая сборка **ещё не вступила в силу**, нужно перезапустить соответствующий процесс.
- `current_version` в `/api/status` — версия **самого launcher**. Версию дочерних процессов смотрите в `procs[].running_build.version`. Смешивать их нельзя, иначе вывод будет неверным.

При ручном тестовом развёртывании явно указывайте семантический номер версии, чтобы потом можно было проследить происхождение:

```powershell
go build -trimpath -ldflags "-s -w -X 'rf4server/internal/buildinfo.Version=<семантический тег>' -X 'rf4server/internal/buildinfo.BuildTs=<метка времени UTC>' -X 'rf4server/internal/buildinfo.GitCommit=<короткий SHA коммита>' -X 'rf4server/internal/buildinfo.SourceDir=<каталог checkout>'".Replace('\','/') -o .deploy/gameserver.exe ./cmd/gameserver
```

Дизайн и компромиссы см. в [deploy-self-verify](../specs/changes/deploy-self-verify/spec.md).

## Подключение клиента

Клиент должен разрешать имя хоста входа в адрес шлюза и доверять сгенерированному HTTPS-сертификату. Для клиентов, использующих хост входа по умолчанию, добавьте в файл hosts такую запись:

```text
127.0.0.1 api.rf4game.ru
```

Если клиент обращается и к другим именам хостов входа, их тоже нужно направить на шлюз и предоставить сертификат, покрывающий эти имена.

Сначала один раз запустите шлюз, чтобы он сгенерировал `certs/server.crt` и `certs/server.key`, а затем доверяйте `certs/server.crt` только в среде локального тестирования. Сертификат самоподписанный. Закрытый ключ распространять нельзя.

`gateway.advertise_host` и `gateway.advertise_port` включаются в ответ на вход. Клиент использует эти два значения для установки realtime-соединения.

## Данные

Основная база данных — это файл SQLite, обычно `data/rf4server.db`. Им совместно пользуются gameserver, gateway и встроенная админка, включён режим WAL.

Статический каталог хранится в `server_data/static.sqlite3` и во время работы подключается только для чтения. Модель изоляции подробно описана в [static_runtime_isolation.md](static_runtime_isolation.md).

Перед обновлением релизного пакета выйдите из launcher, убедитесь, что все сервисы остановлены, а затем сделайте резервную копию `data/`, `config.yaml` и `certs/`. Сохраните прежний релизный пакет, чтобы при необходимости восстановить его вместе с резервной копией данных до обновления. Не перезаписывайте существующие сохранения пустой базой, инициализированной новой версией. Не выкладывайте и не передавайте эти рабочие данные и ключи.

`seed` импортирует статические таблицы в основную базу как копию для миграций и совместимости. Во время работы чтение перечисленных на уровне хранилища статических таблиц перенаправляется в схему `static`, доступную только для чтения.

## Безопасность и ограничения протокола

- Процесс входа через шлюз не аутентифицирует игровые учётные записи. Он выдаёт токен для настроенного ID пользователя, а realtime-соединение принимает токены с корректной структурой, даже если они не зарегистрированы в текущем хранилище токенов. Считайте границу сетевого доступа границей доверия и не выставляйте сервис в публичный интернет.
- Полный токен входа — это ключ RC4. Входящий и исходящий потоки RC4 непрерывны между кадрами. Выделение кадров, шифрование и запись в сокет должны идти по порядку через записывающую сторону сессии.
- ACK нужно отправлять до обработки кадров клиента. Изменение этого порядка ломает протокол клиента.
- Серверные пуши клиенту должны использовать ожидаемую структуру value верхнего уровня и проходить проверку контракта ответа. Недопустимые пуши отклоняются и не отправляются.
- Интервал keepalive мировых часов должен быть меньше таймаута соединения клиента. По умолчанию это 5 секунд. Клиент разрывает соединение примерно через 10 секунд без входящих данных. Мировые часы используют UTC.
- Привязывайте launcher, туннель и порты наблюдения к доверенным сетевым интерфейсам. Замените все учётные данные и ключи по умолчанию.

## Промпт для развёртывания с помощью ИИ-агента

Этот промпт можно отдать агентам вроде Codex, Dsh, Doubao, WorkBuddy и т. п., предварительно подставив реальные пути на вашей машине:

```text
Помоги развернуть и запустить rf4_server_simulator из каталога <каталог проекта> на этом компьютере с Windows.

Сначала проверь:
- версию Windows и запущен ли текущий процесс с правами администратора;
- установлен ли Go и не ниже ли версия 1.27.3;
- свободны ли порты 443, 9341, 9401, 9500-9502.

Затем выполни следующее:
1. Прочитай README.md, config.yaml и docs/deploy.md и объясни, какие действия выполнишь.
2. Собери проект и убедись, что в bin появились gateway.exe, gameserver.exe, seed.exe и launcher.exe.
3. Проверь, что gateway.tunnel.psk и game.tunnel.psk в config.yaml совпадают, а sqlite.static_path указывает на server_data/static.sqlite3.
4. Сделай резервную копию C:\Windows\System32\drivers\etc\hosts, затем направь api.rf4game.ru и api.rf4game.com на 127.0.0.1.
5. Один раз запусти gateway, чтобы создать certs/server.crt и certs/server.key, и подскажи мне, как установить server.crt в «Доверенные корневые центры сертификации». Не загружай и не передавай закрытый ключ.
6. Запусти bin\launcher.exe и проверь http://127.0.0.1:9500, http://127.0.0.1:9500/#admin и проверки работоспособности всех сервисов.
7. Исправляй только сборку и конфигурацию запуска, не меняй бизнес-логику. На каждом шаге сообщай, что выполнено, какой результат и причину сбоя. Когда нужны права администратора, остановись и дождись моего подтверждения.
```
