# Процесс отладки (баги протокола)

Цель: **получить доказательства за один прогон воспроизведения, а не гадать.**
Все инструменты лежат в `tools/`, запускаются через `powershell -ExecutionPolicy Bypass -File`.

## Замкнутый цикл из трёх шагов

1. **Воспроизведение**: запустите `tools\trace.ps1` и попросите пользователя один раз выполнить действие в игре.
2. **Сбор доказательств**:
   - на сервере: перехваченный hex запроса/ответа `cmd=xx/y`;
   - на клиенте: `tools\clientlog.ps1` даёт стек исключения (есть стек — есть метод и поле).
3. **Локализация**: `tools\proto.ps1 <команда>` показывает DTO / wire-класс / поля / класс элементов / args code этой команды, затем сверьте с декомпилированными файлами клиента, чтобы подтвердить тип приведения. **Сначала смотрите таблицу, потом меняйте код.**

## Инструменты

### proto.ps1 — словарь протокола (самый частый)

```powershell
.\tools\proto.ps1 21/2                # профиль команды
.\tools\proto.ps1 class hlopebmchhp   # поля и args code одного wire-класса
.\tools\proto.ps1 list                # список команд с профилями перехвата
```

Вывод включает: смысловое имя, DTO ответа, wire-класс, type_id, op/имя/смысл каждого поля, **класс элементов и нужный args code** для полей-массивов, путь к декомпилированному файлу клиента и тип приведения.

Типичное применение: чтобы отправить массив объектов, смотрите прямо `args code=xxx`, не нужно перебирать три таблицы.

### trace.ps1 — перехват одного взаимодействия

```powershell
.\tools\trace.ps1                      # по умолчанию 120 секунд, автоматически скрывает частые команды вроде 24/1
.\tools\trace.ps1 -Restart             # сначала перезапустить gameserver, затем перехватывать
.\tools\trace.ps1 -Seconds 300 -Filter 'cmd=21/|cmd=22/'
```

Вывод одновременно пишется в `logs\_trace.txt`. Частые отчёты о позиции (`24/1`) по умолчанию фильтруются, иначе кольцевой лог вытесняется за несколько секунд.

### clientlog.ps1 — исключения клиента

```powershell
.\tools\clientlog.ps1 -Last 10 -Frames 8
.\tools\clientlog.ps1 -Since '12:01'
```

`Player.log` обычно сбрасывается на диск **только при выходе из игры**. Если файл пуст, сначала закройте клиент, потом смотрите.

### Другие точки наблюдения

- Панель управления <http://127.0.0.1:9500>: состояние процессов, кольцевой лог в памяти (последние 800 строк на процесс).
- Работоспособность и метрики: `/healthz`, `/metrics` на `9501` (gateway) и `9502` (gameserver). Админка доступна прямо по `9500/admin/`.
- Переключатель трассировки команд: наличие файла `data/trace_cmds.on` или переменная окружения `RF4_TRACE_CMDS=1`.
- Примечание: в Windows **метаданные каталога** (размер/время) у `logs\*.log` **отстают**. Чтобы понять, пишется ли лог, смотрите хвост файла, а не `Length`.

## Подтверждённые факты протокола (не наступайте снова)

| Пункт | Вывод |
|---|---|
| Корневой массив 21/1 | args code **144** (`ookkpknacja`/505, элемент `keialdedcnp`) |
| Слот f3 в 21/1 | клиент приводит к `oinpmjophkh[]` → нужно отправлять **обычный массив u32** (0x05). Если отправить typed_u32arr (0x07), будет InvalidCastException, и вся строка недействительна |
| Массив компонентов 21/2 | класс элемента `poolccanfhd` = `hlopebmchhp`/504 → args code **143** |
| Поле 5 у poolccanfhd | `ojoboopbaec[]` = `hpopgbjohpk`/507 → даже пустой массив нужно отправлять с args code **146**, отправка null приводит к падению `foreach` на клиенте |
| 21/5 | args code **145** (пустой список обмена) |
| Массивы экземпляров карточек/альбомов | реальный реестр типов клиента: **362** = `ipdpoaiekem`, **364** = `imdcjllgdcn`; 363 — это `phjbhljooid`, определение альбома. Используйте явное отображение `by_elem`, нельзя подменять синтезированными значениями `by_type_id` или незарегистрированными именами DTO |
| Синхронизация вставки карточки в альбом | список обновлений 800 одновременно отправляет исходную карточку и альбом, список удаления пуст. StorageType у исходной карточки остаётся 18, родительский GUID указывает на альбом. 4/1, 4/4, 4/5 тоже должны включать уже вставленные исходные карточки, клиент заполняет ячейки по родительскому GUID. Снимок f0 альбома не заменяет карточки в инвентаре |
| Детали удилища | мастерская клиента отрисовывает список `gcfcdnfmnbh` из `f5` удилища. Заводские детали (бланк/рукоять/кольца) нужно записывать и в f5, записи только в f0~f2 недостаточно |
| Производная таблица сборки | `rig_component` односторонне проецируется из `f5`. В исторических данных она может быть пустой, `reconcileRigProjection` способен её заполнить |
| Список игроков чата 24/4 | клиент возвращает тип `int[]`, используйте обычный массив u32. Карточка профиля 24/19 — `dgbmlekfpbg`/2002, обёрнутая в bytes |
| «Отправить сообщение» игрока | используется личная почта 19/1, параметры — UID получателя и текст, ответ null. Пуш 19/10 args(524)[11062]. Это не 24/10 (общий чат) и не 24/27 (рассылка) |

## Чек-лист перед правкой кода протокола

1. С помощью `proto.ps1 <cmd>` подтвердите класс ответа, op поля, класс элементов массива и args code;
2. По `.cs` клиента подтвердите целевой тип приведения (`lpdfanjcalm<T>`);
3. После правки сначала выполните `go build`, перезапустите один процесс (через API панели или `.\tools\trace.ps1 -Restart`);
4. Воспроизведите на клиенте один раз и смотрите одновременно серверный trace и `clientlog.ps1`. Исправлено только тогда, когда стек исключения исчез;
5. При неудаче **сначала получите новый стек исключения**, не меняйте поля вслепую.

## Сборка (важно)

```powershell
.\tools\build.ps1            # собирает только gameserver (стандартные параметры: -trimpath -s -w -ldflags version)
.\tools\build.ps1 all        # gateway/gameserver/seed
```

- **Обязательно сохраняйте -s -w**: неочищенный бинарник на 26 МБ блокируется Windows Smart App Control (An Application Control policy has blocked this file), а очищенный на 18 МБ работает нормально.
- Нельзя перезаписать целевой exe, пока он запущен. Сначала остановите процесс (stop в панели) или соберите другую цель.
- Отдельный перезапуск сервера: POST http://127.0.0.1:9500/api/restart?name=gameserver.
