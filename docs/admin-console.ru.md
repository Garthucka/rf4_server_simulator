# Консоль управления

Консоль управления встроена прямо в `launcher`. В неё входят через вкладку «Админка» единого центра управления `http://127.0.0.1:9500`, отдельный порт `8080` больше не слушается. HTTP-обработчик admin смонтирован в `/admin/`, API фронтенда использует `/admin/api/*`. Внутренний обработчик по-прежнему держит маршруты `/api/*`, чтобы было удобнее тестировать и отлаживать отдельно. Консоль аутентифицируется по учётным данным администратора из `config.yaml`. После успешного входа возвращается JWT, который используется консолью и API.

Этот интерфейс может изменять данные игроков, выдавать предметы, настраивать экономику и управлять сессиями. Открывайте его только на доверенных сетевых интерфейсах.

## Управление игроками

- Поиск игроков по UID или имени.
- Редактирование уровня, опыта, серебра, золота и банковского вклада.
- Просмотр и изменение содержимого рюкзака и садка.
- Добавление и удаление рыбы.
- Редактирование мастерства по категориям рыболовных навыков.
- Выдача предметов из каталога и удаление существующих.
- Кик онлайн-игрока и бан.

Изменения, затрагивающие клиентов онлайн, отправляются через очередь команд gameserver.

Уровни навыков общие для пар «ручная удочка и болонская удочка» и «спиннинг и пистолетная рукоять». Для каждой группы учитывается только одно вложение. Обучение или сброс любого из пары синхронизирует всю группу, а пороги мастерства по каждому пункту остаются независимыми. Исторические узлы читаются по максимальному уровню в группе, старые записи массово не переписываются, подарочные очки за уровень и уже имеющиеся дополнительные очки не корректируются.

## Магазин

- Базовый каталог магазина — данные только для чтения.
- Переопределённые цены и остатки по магазину и предмету хранятся отдельно.
- Цены и остатки можно вернуть к значениям из базового каталога.
- Консоль, просмотр магазина и расчёт покупки используют одну и ту же логику разбора каталога.

Порядок разбора и объём переопределений подробно описаны в [shop_catalog.md](shop_catalog.md).

## Настройки рыбалки

- Выбор водоёма и настройка вероятности и времени поклёвки.
- Включение и отключение видов рыбы и настройка относительного веса.
- Добавление видов из полного пула рыбы.
- Сброс конфигурации водоёма к статическим значениям по умолчанию.

Последующие розыгрыши рыбы и таймеры поклёвки читают эти изменения без перезапуска сервера.

«Новая логика наживки» — переключатель для всех водоёмов, по умолчанию выключен. После включения рыба отбирается по списку карты, включению и отключению в админке, распознанной наживке и локальным реальным сочетаниям снастей. Если подходящей рыбы нет, запасной пул не используется. Наживка, которую рыба явно не ест, исключается первой. После выключения возвращается прежний процесс выбора рыбы. Переключатель сохраняется независимо от отладочных пресетов и влияет на последующий выбор рыбы не более чем через 30 секунд. Рыба, уже взявшая наживку, не пересчитывается. Поведение GM-команды «следующая рыба» сохраняется.

Номера районов морской карты поддерживаются. В Норвежском море номер района определяется по водоёму в точке заброса. Рыба, у которой в гайде указано «морская карта, район NN», клюёт только в соответствующем районе. Запись «морская карта, район не ограничен» требует лишь, чтобы игрок сейчас находился на морской карте. Если определить точку заброса не удалось, ограничение нейтрально. Плавание по течению, `jig-ступенчатая проводка` и движение наживки в воде определяются по битам состояния анимации снасти `14/7`. Если сообщений о действии нет, по этому признаку рыба не ограничивается. Билет на лодку и посадка определяются по сроку действия проверки 3/7 и по realtime-сообщениям `3/10` boat_use: если проверка пройдена или пришло сообщение о посадке, игрок считается на лодке. Получив сообщение о высадке, сервер сразу считает игрока вне лодки. Если сообщения о высадке нет, игрок считается сошедшим только по окончании аренды. Если за эту сессию посадка не встречалась, ограничение нейтрально. Для двух наживок сохраняется прежняя реализация: при нескольких крючках рыба проверяется по наживке каждого крючка, а бонус комбинации сохраняется. Пока не реализованы координаты сетки гайдов для внутренних озёр, консоль показывает эти диапазоны. Нераспознанные сочетания без доказательств реальной ловли пока не допускаются. Правила поставляются вместе с выпуском сервера, автоматически обновлять статистику из сети сейчас не планируется.

## Почта

Отправка игроку текстового письма с нулём или несколькими предметами из каталога во вложении. Количество задаётся отдельно для каждого вложения. Доставку писем выполняет gameserver.

## Журнал аудита

Изменения от административных операций записываются в `audit_log`. Консоль показывает журнал аудита только для чтения.

## API

При единой точке входа ко всем перечисленным путям добавляется префикс `/admin`, например вход выглядит как `POST /admin/api/login`. Кроме входа, все запросы должны передавать JWT как bearer-токен. При отдельной отладке `cmd/admin` по-прежнему используются прямые пути `/api/*`.

```text
POST /api/login
GET  /api/me
GET  /api/dashboard
GET  /api/tunables
POST /api/tunables
GET  /api/players
GET  /api/players/detail
POST /api/players/update
POST /api/players/grant
POST /api/players/items/delete
POST /api/players/keepnet/add
POST /api/players/keepnet/delete
POST /api/players/skills/update
POST /api/players/kick
POST /api/players/ban
GET  /api/catalog/items
GET  /api/stores
GET  /api/stores/items
POST /api/stores/items/update
POST /api/stores/items/reset
GET  /api/fish/areas
GET  /api/fish/config
POST /api/fish/config
POST /api/fish/config/reset
GET  /api/fish/pool
POST /api/mail/send
GET  /api/audit
```
