# Грубый отсев «вода/суша» для поиска рыбы

Это необязательная локальная предварительная обработка: **запускать игру и входить в неё не нужно**. По числовым данным сцен установленного клиента строится таблица «вода/суша», и при поиске рыбы запрос просто смотрит в таблицу. Она не меняет фактическую выдачу рыбы, проверку попадания в воду, веса видов рыбы и данные игрока.

## Генерация и использование

Инструменту нужны Python 3.10+, [UnityPy 1.25.4](https://github.com/K0lb3/UnityPy) (MIT) и [NumPy](https://numpy.org/) (BSD-3-Clause). Они используются только для необязательного офлайн-инструмента и не входят в зависимости времени работы Go-сервиса. Чужие реализации инструмент не копирует. Выполняйте из корня репозитория, заменив заполнитель пути клиента:

```powershell
python -m venv ref/water-env
./ref/water-env/Scripts/python.exe -m pip install UnityPy==1.25.4 numpy
./ref/water-env/Scripts/python.exe tools/fish_query_water.py --client-data '<каталог клиента>/rf4_x64_Data' --output ref/fish_query_water.json --audit ref/water-grid-audit.json
```

По умолчанию обрабатываются все внутренние карты из таблицы поддержки поиска рыбы. В конец команды можно добавить идентификаторы сцен, чтобы сгенерировать только указанные карты. Такой вывод содержит только указанные карты и не сливается со старой таблицей. Файл аудита фиксирует по каждой карте общее число ячеек, число сохранённых и отброшенных, использованные типы водоёмов и SHA256 выходного файла. Нераспознанные карты попадают в `unsupported`, заглушки «вся суша» или «вся вода» не создаются.

Сгенерированный файл остаётся только локально и не распространяется с репозиторием, PR или установочным пакетом. Изображения клиента, сетки, полные карты высот и файлы ресурсов тоже не коммитятся. Инструмент только читает каталог клиента, вывод должен лежать вне каталога установки. После обновления клиента, калибровки карты или изменения правил выборки таблицу нужно сгенерировать заново.

Для использования отдельно скопируйте `fish_query_water.json` в **`data/` рабочего каталога игрового сервиса** и перезапустите игровой сервис. Инструмент генерации сам ничего не развёртывает, не перезапускает сервис и не управляет клиентом. Файл можно указать и через `RF4_FISH_QUERY_WATER_FILE`. Если переменная не задана, последовательно проверяются `data/` и `server_data/` рабочего каталога, а также `data/` каталога программы и `server_data/` на уровень выше.

Данные загружаются при первом запросе и кэшируются в процессе. Если ни по одному пути по умолчанию файла нет или в таблице отсутствует эта карта, используется прежний региональный запрос, в результате расчёта `WaterFiltered` равен false, а `Notes` записывает «нет данных вода/суша для этой карты». Игровая справка объясняет это правило единообразно, обычные ответы это не повторяют. Если явно указанный файл не существует, повреждён или его диапазон не совпадает с исходным кодом, по-прежнему возвращается сообщение о недействительных данных, а данные не используются молча неверно. Морская карта, ручные координаты и запросы с отключённым распределением косяков эту таблицу не используют.

## Правило пяти точек

1. Используется пересечение рельефа и бумажной карты и сетка `floor(мировой X/40), floor(мировой Z/40)` из [пересчёта координат для поиска рыбы](fish-query-coordinates.ru.md).
2. Для каждой обрезанной ячейки берутся центр, левый нижний, правый нижний, левый верхний и правый верхний углы. Угловые точки на верхней границе смещаются внутрь ячейки не более чем на одну миллионную метра, чтобы не попасть в соседнюю ячейку. Центр от смещения углов не меняется.
3. Точка считается водой, только если она находится в пределах распознанного водоёма и высота рельефа ниже базовой поверхности воды.
4. **Если вода хотя бы в одной точке, ячейка сохраняется целиком. Отбрасывается только ячейка, где все пять точек не вода.** Фильтрация «вода/суша» выполняется раньше грубого отсева зон без наживки, не сдвигает ячейки, не перенумеровывает их и не меняет вероятности в сохранённых ячейках.

Рельеф сэмплируется билинейно по высоте с наложением мирового начала Y. Из перекрывающихся Terrain берётся наивысшая поверхность, чтобы остров не считался подводным рельефом нижнего слоя. Текущее кодирование высот сверяется с независимыми экстремумами высот, если распознать нельзя, карта отклоняется. К размерам Terrain масштаб и поворот объекта повторно не применяются.

Водоём определяется базовой поверхностью воды, областью триггера и применимой плоской сеткой поверхности воды. Для Water4 дополнительно проверяется покрытие треугольной сеткой поверхности воды. Для Water2 и интерфейса Crest используются приближения по области триггера и высоте рельефа. Берутся только активные водоёмы или нормальные/резервные водоёмы, на которые ссылается контроллер активного водоёма, любые отключённые объекты за водоём не принимаются.

## Формат данных

Верхний уровень содержит `schema_version: 1`, `cell_size: 40`, `sampling: "center_corners_any"` и `maps`, индексированные по идентификатору сцены. Для каждой карты хранится:

- `bounds`: обрезанные мировые `[minX,minZ,maxX,maxZ]`.
- `min_x`, `min_z`: минимальные номера мировой сетки. `width`, `height`: число ячеек сетки.
- `samples`: порядок с внешним X и внутренним Z. Индекс `(ix-min_x)*height+(iz-min_z)`.
- Целое число `0..31` на ячейку: пять бит по порядку обозначают центр, левый нижний, правый нижний, левый верхний, правый верхний. `0` — отброшено, не ноль — сохранено, `31` означает, что вода во всех пяти точках, но не то, что вся ячейка водная.

Сервер проверяет формат, правила выборки, число ячеек, диапазон и текущую сетку сканирования, максимум 76 ячеек на ось. Время генерации и `unsupported` в выводе служат локальной диагностике и в расчёте вероятностей не участвуют.

## Ограничения и проверка

Это грубый отсев явной суши, а не полноценная физика клиента. Смешанные прибрежные ячейки сохраняются, а центр ячейки всё равно может оказаться на суше. Узкие протоки или маленькие водные поверхности могут быть пропущены пятью точками. Не моделируются волны, приливы, эффекты обрезки Crest, дыры рельефа, скалы, мосты, здания и достижимая дальность заброса, а фактическая глубина воды не учитывается в вероятностях по областям. Карты с неподдерживаемыми дырами рельефа прямо объявляются неподдерживаемыми.

Тесты на синтетических данных не требуют ресурсов клиента:

```powershell
./ref/water-env/Scripts/python.exe -m unittest discover -s tools -p test_fish_query_water.py -v
go test ./internal/gameserver -run '^TestFishQuery' -count=1
```

Результаты генерации по реальным картам и офлайн-пересчёт запросов не равны покартовой приёмке в реальной игре. Отправьте в игре «помощь», чтобы увидеть правила и ограничения грубого отсева по пяти точкам. Обычные запросы это не повторяют и не заявляют, что вся ячейка — вода или достижима.
