# Развёртывание через Docker Compose

На Windows и macOS используйте Docker Desktop. На Windows нужно включить Linux-контейнеры. На Linux используйте Docker Engine и плагин Compose v2. Образ собирается локально из исходников и поддерживает AMD64 и ARM64. Go на хосте устанавливать не нужно.

Перейдите в каталог `docker/` репозитория и выполните:

```sh
docker compose up -d --build --wait
docker compose ps -a
```

Compose сначала запускает `seed` для инициализации SQLite. После успеха стартует `gameserver`, затем `gateway` и отдельная веб-админка. В нормальном состоянии `seed` показывает код выхода 0, а остальные три сервиса показывают healthy.

| Адрес на хосте | Назначение |
| --- | --- |
| `http://127.0.0.1:8080/` | Веб-админка, учётная запись по умолчанию `admin`, пароль `admin123` |
| `https://127.0.0.1:443/` | HTTPS-вход клиента |
| `127.0.0.1:9341` | Realtime-соединение клиента |
| `127.0.0.1:7515` | Порт совместимости с HTTP-входом старого CN-клиента |

По умолчанию порты привязаны только к loopback-адресу хоста. Внутренние порты туннеля и наблюдения обслуживаются сетью Compose. Если в Linux с rootless Docker не хватает прав на привязку 443, для проверки запуска можно выбрать высокий порт через переменную `RF4_HTTPS_PORT`. Клиентам, которые жёстко обращаются к 443, всё равно нужен порт 443. Порт админки меняется переменной `RF4_ADMIN_PORT`.

Для развёртывания в локальной сети создайте в этом каталоге файл `.env`. Установите `RF4_BIND_IP` и `RF4_GATEWAY_ADVERTISE_HOST` равными локальному IPv4 хоста. Для `RF4_ADMIN_PASSWORD`, `RF4_ADMIN_JWT_SECRET` и `RF4_DOCKER_TUNNEL_PSK` задайте отдельные случайные значения, затем выполните команду запуска. Админка доступна по порту 8080 этого IPv4. Служба входа шлюза рассчитана на доверенную локальную сеть, не пробрасывайте эти порты на роутере.

Клиент RF4 запускается отдельно. Настройте hosts и доверие к сертификату в системе, где запущен клиент, по [инструкции по подключению клиента](../docs/deploy.ru.md#подключение-клиента). После того как шлюз сгенерирует сертификат, скопируйте публичный сертификат в текущий каталог:

```sh
docker compose cp gateway:/app/certs/server.crt ./server.crt
```

```sh
docker compose logs -f
docker compose down
```

`docker compose down` останавливает и удаляет контейнеры. Сохранения игроков и HTTPS-сертификаты хранятся в именованных томах `player-data` и `gateway-certs`. Чтобы продолжить, достаточно снова выполнить команду запуска. `docker compose down -v` выполняйте только тогда, когда нужно очистить эти два тома. После обновления кода снова выполните `docker compose up -d --build --wait`. Из корня репозитория используйте `docker compose -f docker/compose.yaml` с нужной подкомандой.

## Идентификатор сборки образа

По умолчанию образ формирует `Version` / `BuildTs` из времени сборки и помечает источник как `SourceDir=docker`. Чтобы связать образ с конкретным коммитом, передайте значения перед запуском:

```sh
RF4_GIT_COMMIT="$(git rev-parse --short HEAD)" \
RF4_SOURCE_DIR="$PWD" \
docker compose up -d --build --wait
```

В CI или релизной среде также нужно явно задать `RF4_BUILD_VERSION` и `RF4_BUILD_TS` в формате UTC (`yyyyMMddHHmmss`). После развёртывания метрику `rf4_build_info` можно посмотреть по `/metrics` внутри контейнера.
